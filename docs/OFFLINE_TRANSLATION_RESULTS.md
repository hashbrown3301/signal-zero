# Offline translation implementation and cloud validation

Date: 2026-10-01. Branch: `Upgradation`. These are CPU/JVM measurements in the
two-core, 8 GiB cloud, **not Android device latency or a translation accuracy score**.

## What runs on the phone

Hold to talk, release, recognize the completed phrase, translate to the independently
selected listening language, and play that language's voice. Incoming text over
local Wi-Fi/Bluetooth follows the same receiver-side path. Source text and wire
language codes remain unchanged. Same-language playback bypasses translation.
Absent translation models, generation errors and absent voices are explicit states;
the app keeps original/translated text and never substitutes another language's voice.

The model is `Xenova/nllb-200-distilled-600M`, revision
`261c31d1a5732c67cdd16d80e8d6088507c7ccea`. Downloads/imports verify all three
immutable source artifacts. No Hugging Face token or conversation network request
is required. The raw model ZIP is 899 MB; its generated decoder adds about 475 MB
of private storage. The first preparation can temporarily require further space.

Native SentencePiece encoding/decoding matches Hugging Face reference IDs and text
in all ten scripts. The encoder uses source-tag prefix + EOS; the merged decoder
forces the requested target tag and reuses its attention cache. Calls run off the
UI thread with two CPU threads. Translation results have a 128-entry LRU cache;
source/output token limits fail explicitly rather than truncating text silently.

## Measured output-layer optimization

The public quantized decoder expands a 256,206-by-1,024 vocabulary matrix into
floating point in both decoder branches. This consumed gigabytes of RAM.
The new decoder instead dynamically quantizes the final hidden activation and
uses the existing quantized vocabulary weights with integer matrix multiplication,
then rescales logits. This adds activation quantization at the output layer; it is
not mathematically identical to the previous floating-point projection.

The app applies a five-edit, 1,854-byte patch as a streaming file copy. It hashes
every original and generated byte and atomically activates only the exact tested
derived model. The original weights remain unchanged. This uses a 64 KiB buffer,
so Java never holds the 475 MB file in memory. Developer tooling reproduces and
checks the graph, compact patch, and generated artifact:

```sh
python scripts/optimize_translation_decoder.py \
  dist/translation/nllb/decoder_model_merged_quantized.onnx \
  dist/translation/nllb-optimized/decoder_model_merged_quantized.onnx \
  --patch-json dist/translation/decoder-patch.json
```

Use `scripts/requirements-native-validation.txt` for the pinned developer tooling.
Generated decoder SHA-256:
`cb63d93b85e2bc45c0e5816a3177dfab9a7ef7361e77696773fd0191898b2da3`.

| CPU configuration | Short phrase translation | Peak process RSS |
| --- | --- | --- |
| Original decoder, arena/prepacking enabled | 1,040 ms median, 90 directions | about 3.90 GiB |
| Optimized decoder, prepacking enabled, arena disabled | 314 ms median, 90 directions | about 2.37 GiB |
| **Selected: optimized decoder, prepacking/arena/memory patterns disabled** | **555.5 ms median, 90 directions (288–737 ms)** | **about 1.90 GiB** in the separate four-direction process |

The selected configuration saves RAM at a CPU cost compared with prepacking.
Its initial four-direction load took 8.2 seconds including the first streaming
decoder preparation. Cold loading is separate from warm translation and may still
be noticeable. Repeated model loading, phone storage speed, long phrases, target
voice loading, speech recognition, synthesis and thermal throttling affect total
release-to-first-audio latency. A translation-only timing cannot represent that total.

Final selected configuration: **158 JVM tests, zero failures/errors/skips**, including
native inference across all 90 directions and ten-script tokenizer parity;
**28 Python tests passed**. All arm64-v8a, armeabi-v7a and x86_64 debug APKs built.
Each APK contains exactly one shared native ORT library and both Java/Extensions JNI
libraries. Building the 32-bit APK does not enable translation on 32-bit phones.
Raw final outputs and timings are in
[offline_translation_cloud_results.json](offline_translation_cloud_results.json).
Final cold load was 5,690 ms with the generated model already cached; median text
translation decreased about **47%** from 1,040 to 555.5 ms. An earlier selected
configuration pass measured 594.5 ms (about 43% lower); both passes are recorded. The final outputs also
matched 89/90 original examples. These are short-phrase smoke passes, not phone
percentiles or a general latency guarantee.

The prepacked optimized decoder produced the exact same text as the original on
89/90 short request-for-water examples. The one difference was a Bengali polite
verb form for Malayalam input. All 16 additional English/Hindi name, quantity,
negation and time outputs matched in Hindi, Telugu, Odia and English. These checks
establish limited output stability; they do not measure general accuracy. The
existing Hindi-to-English name error **Rohan → Rohn** remained in both models.

## Reproducing checks

Fetch speech/native dependencies with `scripts/fetch_models.py`; an existing speech
setup can use `--runtime-only`. Generate an importable offline model with
`python scripts/fetch_translation_model.py --zip`. Python tests:

```sh
.venv/bin/python -m unittest discover -s scripts/tests -v
```

Normal `testDebugUnitTest` runs use no large-model downloads. Real native tests are
opt-in: set `ITANTRA_NLLB_DIR` to the verified raw three-file folder and
`ITANTRA_ORTX_LIBRARY` to the desktop Extensions 0.13.0 shared library (printed by
`onnxruntime_extensions.get_library_path()`). On Linux the Python extension requires
`LD_PRELOAD` of the matching `libpython3.12.so` when loaded by Java. This is desktop
test setup only; the Android Extensions library has no Python dependency.
Set `ITANTRA_NLLB_ALL_PAIRS=1` to exercise all 90 directions, then run
`testDebugUnitTest assembleDebug`. The native tests also compare all ten tokenizer
scripts against the reference fixture and check a quantity/negation translation.

The cloud uses the workspace Java proxy helper and Maven mirror described in
`/workspace/AGENTS.md`; those machine-specific files are not repository dependencies.

## Device and release limits

The app permits translation on 64-bit phones with at least 4 GB physical RAM and
2.5 GB currently free memory after speech models have loaded. Six GB or more is
recommended pending device measurements. This is a conservative allocation check,
not a tested phone support matrix. Two-GB/32-bit phones retain recognition and
same-language playback but cannot load this translation engine.

No Android emulator or physical device is attached here. Actual microphone,
Bluetooth, target voice quality, background behavior, small-screen accessibility,
phone memory and end-to-end latency remain device acceptance checks. A slow peer
can exceed the existing 60-second delivery deadline. Native calls finish before
their resources can be released; cancellation is checked between decoder steps.

Sherpa supplies native ORT 1.27.1; Java JNI uses 1.27.0, with the duplicate runtime
removed deterministically. Extensions 0.13.0 provides both SentencePiece operators.
Its published ARM64 binaries have 4 KiB segment alignment, so a rebuilt 16 KiB
compatible version and device checks are required before a Play release.

NLLB is CC BY-NC 4.0 and its upstream model card specifies research rather than
production deployment. This build is for noncommercial evaluation. Suitable model
licensing, held-out human-reviewed translation accuracy and device checks are
required for a production product. See [OFFLINE_TRANSLATION_VALIDATION.md](OFFLINE_TRANSLATION_VALIDATION.md).
